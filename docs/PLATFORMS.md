# Platform setup and capabilities

The executable and tests use fixtures. Provider registrations, permissions, review and billing apply only when a consuming app enables live access. Adapters never automatically replay a write. Keep the original draft key and reconcile an uncertain result before trying again.

## Confidential exchanges

Threads, Facebook Login, Instagram Login, and LinkedIn's standard code flow need a trusted service for the confidential token exchange. Supply a `ConfidentialOAuthExchange` that sends the authorization code and registered redirect URI to your authenticated service. Configure the client ID, allowed redirect URI, provider and app secret on the service. Bind each exchange to the initiating app session, reject arbitrary redirects or provider URLs, and exchange each code once. Return the user access token, known granted scopes, expiration date, and any refresh credential supported by the provider. Keep the app secret on the service. If the adapter uses broker refresh, reconnect when the service cannot renew a session. SocialKit ships the protocol and an in-memory example implementation.

For production OAuth, supply an `OAuthBrowser` using the system browser authentication session and a redirect URL registered with the provider. Use a callback that your app can verify and receive. Apps targeting HTTPS callbacks should account for platform availability of Apple's HTTPS callback matching or provide their own authenticated handoff. [Apple browser authentication](https://developer.apple.com/documentation/authenticationservices/aswebauthenticationsession).

Meta credential lifecycle is provider-specific. Import an Instagram or Threads long-lived token, or exchange the short-lived code/token through the provider's confidential exchange outside the client. Set `metaLongLivedRefreshEligibleAt` only when the token is confirmed long-lived. SocialKit uses the provider’s access-token renewal grant, and leaves a token’s expiry unknown until supplied by the provider or importer. Facebook Page credentials can retain the source user grant in the credential store to recover the same Page from `/me/accounts`. The Page and source grant have independent lifetimes. [Meta's Facebook Page token example](https://www.postman.com/meta/facebook/request/bqfxwbp/get-access-tokens-of-pages-you-manage), [Threads long-lived tokens](https://developers.facebook.com/docs/threads/get-started/long-lived-tokens/), [Instagram Business Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login/).

## Threads

Configure a Meta app with the Threads use case. The adapter uses Threads Graph API v1.0. The scopes for basic access, publish, read replies and write replies are `threads_basic`, `threads_content_publish`, `threads_read_replies`, and `threads_manage_replies`. Use the confidential exchange to issue the Threads user token. The adapter creates and publishes text, image, and video containers. Pass publicly reachable HTTPS URLs for images and video. Reply creation uses a parent post ID. It supports post lookup, the account’s posts, paginated replies, hide and unhide with `threads_manage_replies`, repost creation, and own-reply deletion with `threads_delete`. Refresh an eligible long-lived user token before it expires. Likes, undoing reposts, and analytics are outside this adapter. [Threads API](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api).

## Facebook Pages

Configure a Facebook Login app. The adapter uses Graph API v27.0. The broker exchanges for a Facebook **user** token. The adapter uses that token to enumerate authorized Pages and stores the selected **Page** token for posts and engagement. Select a Page ID when multiple eligible Pages are returned. Scopes include `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, `pages_read_user_content`, and `pages_manage_engagement`. The authorizing user needs the relevant Page tasks and the app needs production access to the requested permissions. The adapter covers Page text posts, post lookup and pagination, adding, listing and deleting comments, and like or unlike as the Page. Reconnect to reacquire an invalid Page token. Personal Facebook profiles are outside this adapter. [Pages API](https://developers.facebook.com/docs/pages-api/).

A Page credential with verified `pages_show_list`, `pages_read_engagement`, and `pages_manage_posts` can publish a single hosted HTTPS photo with an optional caption. The authorizing user needs the Page's `CREATE_CONTENT` task. SocialKit sends `POST /{page-id}/photos` and records the returned `post_id` as the feed receipt. A photo-object ID alone leaves the outcome uncertain. Keep the photo reachable without credentials while Meta fetches it. The request follows Meta's documented Page Photos shape and targets v27.0. Live publishing with the configured Meta app remains to be validated. [Page Photos reference](https://developers.facebook.com/docs/graph-api/reference/page/photos/), [Meta SDK example](https://github.com/facebook/facebook-php-business-sdk/blob/main/examples/PagePhotosPost.php).

Provider-held Page scheduling is disabled. Meta documents scheduling fields including `published=false`, `scheduled_publish_time`, and `unpublished_content_type=SCHEDULED`. Before enabling any post type, validate create, status, and cancel against Graph API v27.0 using the configured app and a designated test Page, then persist the Page post ID and reconcile ambiguous create and cancel outcomes. Indie Dev Buddy's local queue sends at the selected time while the app is open and the Mac is awake.

## Instagram

The adapter supports two distinct authentication routes for Business or Creator accounts. Both use Graph API v27.0 and the same media operations, but their hosts, token types, and permission names differ.

### Instagram Login

Use Instagram's own user token for the professional account. The adapter uses the Instagram API host. Grant `instagram_business_basic` for professional media reads, `instagram_business_content_publish` to publish, and `instagram_business_manage_comments` for moderation and replies. This token and these scopes are distinct from Facebook Login. Refresh an eligible long-lived token before it expires.

### Facebook Login with a linked Page

Use a Facebook user token with access to the Page linked to the Business or Creator account. The adapter discovers the user's Pages, verifies the selected Page and its Instagram professional account association, obtains the Page access token, and sends Instagram requests through the Facebook Graph API host. The caller supplies the Instagram professional account ID; it is not the Facebook Page ID. Required permissions include `pages_show_list`, `pages_read_engagement`, `instagram_basic`, and `instagram_content_publish`. Comment actions also need `instagram_manage_comments` and the relevant Page access. If the Page role was assigned through Meta Business Manager, Meta may additionally require `ads_read` or `ads_management`; request `ads_read` when it satisfies the app's access needs. The authorizing user needs the Page's `CREATE_CONTENT` task to publish. This is the Facebook Login (`API setup with Facebook login`) route; a system-user token from Unified Login is a different credential flow.

### Publishing behavior

The adapter creates a media container, polls for a terminal processing result, and publishes a ready container once. Pass an externally accessible HTTPS image or Reel URL. Meta fetches the file directly, so it must remain reachable without an authorization header through processing. SocialKit does not fetch or host it. This path covers single images, Reels, and ordered carousels of 2–10 images or videos. Carousel children are checked before creating the parent. Single-media lookup returns carousel child attachments. Stories, direct file upload, and likes are outside this adapter. [Instagram Login collection](https://www.postman.com/meta/instagram/folder/1z5vxzu/instagram-api-with-instagram-login), [Facebook Login setup](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/get-started/), [Content publishing](https://developers.facebook.com/docs/instagram-platform/content-publishing).

These features remain disabled until the registered login product, API version, grant, and access tier are checked on the configured app. Request additional scopes only for the feature being enabled.

Send `POST /{comment-id}?hide=true` or `hide=false` on `graph.instagram.com`. Owner comments on their own media stay visible. [Comment reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-comment). |
| Instagram insights | Instagram Login uses `instagram_business_basic` and `instagram_business_manage_insights` for the account and media insights edges. ## LinkedIn

Configure Sign In with LinkedIn using OpenID Connect for identity and the appropriate posting product. Member publishing requires `w_member_social`. Organization publishing requires `w_organization_social` and an eligible organization role. Bind the account to its organization URN at connect time to publish as that organization. Read scopes `r_member_social` and `r_organization_social` are separate from write access. Comments and reactions use the corresponding `*_social_feed` scopes. Member reads and programmatic refresh are subject to LinkedIn product access. Use the confidential broker for the standard OAuth flow. The adapter uses versioned REST requests and defaults to `LinkedIn-Version: 202610`. It publishes public posts, initializes and uploads single images and 2–20-image posts from image bytes, and polls image status when the grant allows it. A write-only member grant goes directly from upload to one post attempt because LinkedIn restricts status reads. Native loopback OAuth, comment deletion, video and documents are outside this adapter. [Posts](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-10), [Images](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api?view=li-lms-2026-10), [Versions](https://learn.microsoft.com/en-us/linkedin/marketing/versioning), [OAuth refresh eligibility](https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens).

## X

Configure a public OAuth 2.0 client and its registered callback. The public client ID is app configuration. SocialKit uses S256 PKCE and exchanges and refreshes the token directly. User-context post reads use `tweet.read` and `users.read`, publishing and reposting use `tweet.write`, likes use `like.write`, and refresh needs `offline.access`. API credit and endpoint eligibility remain controlled by X. Rate-limit errors return `Retry-After` when available or the reset time as an HTTP date. HTTP 402 is a separate billing error. Reply retrieval searches the last seven days and expects the conversation’s root post ID. The adapter supports deleting an owned reply. Like and repost operations depend on X granting the app endpoint access. To enable image publishing, create `XAdapter` with `includeMediaWriteScope: true` and connect again to obtain `media.write`. It accepts up to four JPEG, PNG, or WebP images as bytes, with a 5 MiB limit per image. Video, animated GIF uploads, and analytics are outside this adapter. [X OAuth](https://docs.x.com/fundamentals/authentication/oauth-2-0-authorization-code), [Create post](https://docs.x.com/x-api/posts/create-post), [X API access](https://docs.x.com/x-api/getting-started/about-x-api), [Recent search](https://docs.x.com/x-api/posts/search-recent-posts), [Rate-limit headers](https://docs.x.com/x-api/fundamentals/response-codes-and-errors).
