# Adapter audit

Updated 2026-11-10 to reflect the current adapter contracts. Provider documentation review is dated 2026-11-08; verification used fixtures throughout and this audit does not claim live account validation.

| Adapter | Contract checked and changes |
| --- | --- |
| Bluesky | Password sessions and create-only repository writes remain on the configured PDS. Deterministic record keys distribute drafts across the TID clock space; the compatibility URI helper preserves reconciliation of writes created by earlier SocialKit versions. Author feed pagination and public post metrics use AppView without authorization, with returned author identity mapped onto `SocialPost`. Mention resolution returns a DID for native facets. **Shared read model:** provider-returned author identity, reply parent/root references, and account ownership are optional fields on `SocialPost`. Availability depends on each provider endpoint and granted scopes; a missing field means unknown, not false. Meta records now map author identity, reply context, and ownership where the response supplies them.

Meta’s developer site rate-limited some documentation pages. The audit used its official Postman collections and official documentation excerpts where the pages were unavailable.

## Security and verification boundaries

- Bring your own registration. X and Mastodon can authenticate as public clients. Meta and LinkedIn’s standard code flow require the consuming app’s trusted exchange. SocialKit ships the protocol and a fixture exchange.
- Use one client per provider and store to coordinate sign-in and account mutations. Access tokens use the signed app’s data-protection Keychain. The in-memory store is for tests and temporary sessions. Signed Keychain persistence, app review, production token exchange and provider-side permissions remain account-dependent.
- The transport rejects redirects and does not automatically replay writes. An interrupted final publish can require reconciliation against provider state. In-flight media workflows have no persistent resume checkpoint across app termination.
- The SDK emits no request or response logs. If a host adds structured diagnostics, log operation names and sanitized error categories. Never log authorization headers, raw request or callback URLs, response bodies, media, or tokens. Meta token refresh and LinkedIn upload URLs can carry credentials in query parameters.
