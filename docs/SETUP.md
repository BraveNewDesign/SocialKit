# Setup and usage

## Credential storage

Use an app-specific Keychain service and a single `SocialClient` instance per provider and store. The SDK stores device-local, unlocked-only entries in the data protection Keychain. macOS requires the host app’s signing entitlements to identify its Keychain access group. A sandboxed app also needs outgoing network access. For CLI experiments and tests, use `MemoryCredentialStore()`. [Apple Keychain guidance](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains).

Call `client.accounts()` to discover accounts already in the store. `disconnect(_:)` deletes the local credential. To revoke access, use the provider’s settings. Keep credentials, OAuth callback URLs and raw HTTP bodies out of app logs.

## Bluesky

In Bluesky settings, create an app password. Prompt for it using a secure input field. The default PDS is `https://bsky.social`. Supply a different HTTPS origin only if you trust it and it hosts the account. SocialKit sends the app password to that origin during session creation and persists the issued tokens. [Bluesky publishing and app-password guide](https://docs.bsky.app/docs/tutorials/creating-a-post).

```swift
import SocialKit

let client = SocialClient(
    adapter: BlueskyAdapter(),
    store: KeychainCredentialStore(service: "com.example.myapp.socialkit")
)
let account = try await client.connect(.init(
    identifier: handle, appPassword: appPassword
))
let draft = TextPost(text: "Hello from SocialKit")
let published = try await client.publish(draft, as: account.id)
let fetched = try await client.post(id: published.id, as: account.id)
```

This uses the AT Protocol app-password session flow. AT Protocol OAuth and automatic PDS discovery are future work. The OAuth flow requires client metadata, DPoP proofs, pushed authorization requests, and server discovery. [AT Protocol OAuth specification](https://atproto.com/specs/oauth). When an access token expires, call `refresh(account.id)` before a subsequent request. If refresh fails because the session was revoked, reconnect with an app password.

## Mastodon

Use a trusted Mastodon instance with S256 PKCE support (Mastodon 4.3 or later). SocialKit registers an OAuth application on that instance during connection. The registration’s secret is generated by the instance and used during that connection. The app supplies a reverse-domain custom URL scheme for the callback. Use `forceLogin: true` when connecting another account on the same instance. [Mastodon OAuth](https://docs.joinmastodon.org/spec/oauth/).

For SwiftUI, use the system authentication session from your view. Register the custom scheme in the host app’s URL Types. The following method belongs inside a view with access to that environment value. [Apple WebAuthenticationSession](https://developer.apple.com/documentation/authenticationservices/webauthenticationsession).

```swift
import AuthenticationServices
import Foundation
import SocialKit
import SwiftUI

struct MastodonConnectionView: View {
    @Environment(\.webAuthenticationSession) private var browser

    let client: SocialClient<MastodonAdapter>
    let server: URL
    let onConnection: (Result<SocialAccount, any Error>) -> Void

    var body: some View {
        Button("Connect Mastodon") {
            Task {
                do {
                    let redirect = URL(string: "com.example.myapp:/oauth/mastodon")!
                    let account = try await client.connect(.init(
                        server: server,
                        redirectURI: redirect,
                        applicationName: "My App",
                        forceLogin: true
                    ) { [browser] url, callback in
                        guard let scheme = callback.scheme else {
                            throw SocialError.invalidConfiguration
                        }
                        return try await browser.authenticate(
                            using: url, callbackURLScheme: scheme, preferredBrowserSession: .ephemeral
                        )
                    })
                    onConnection(.success(account))
                } catch {
                    onConnection(.failure(error))
                }
            }
        }
    }
}
```

Publish with the same `client.publish(_:as:)` call shown for Bluesky. Mastodon uses the account’s default visibility. Mastodon posts return provider HTML with `textFormat == .html`. Treat it as untrusted when rendering.

## Publishing and recovery

Create and persist one `TextPost` per intent before sending it. Retain the account ID and the full draft across retries. The SDK never automatically retries writes. `SocialError.rateLimited(retryAfter:)` exposes the provider’s optional HTTP header. `SocialError.publishOutcomeUnknown` means the request could have been applied. Preserve the original key and reconcile before another attempt.

- **Bluesky.** Compute the expected record URI using `try BlueskyAdapter.postID(for: draft.idempotencyKey, createdAt: draft.createdAt, accountDID: account.remoteID)`. Fetch the record and compare it with the draft. A duplicate-key error alone cannot establish that the stored record contains the intended text. The key uses a deterministic UUID-derived slot within the draft's creation second, so the same saved draft keeps its URI on retry. A TID has finite space, so a collision remains theoretically possible; do not treat a matching key alone as proof of delivery. For a draft first sent with a SocialKit version before this key change, use `legacyPostID(for:createdAt:accountDID:)` when reconciling its old URI.
- **Mastodon.** The adapter sends the draft UUID as `Idempotency-Key`. Mastodon can retain keys for up to one hour. Check the account’s recent posts after an ambiguous result. A same-key resubmission may create a duplicate if the provider has forgotten the key. [Mastodon status creation](https://docs.joinmastodon.org/methods/statuses/#create).

Operations on different accounts can run concurrently. Calls that overlap for the same account through one client can return `accountBusy`. Refresh and reconnect may rotate credentials, so use that client for account mutations.

## Threads, Facebook Pages, Instagram, LinkedIn, and X

Run `swift run SocialKitExample` for credential-free sign-in and publishing examples. The example uses `HTTPTransport`, `OAuthBrowser`, and `ConfidentialOAuthExchange` fixtures. In a host app, select the provider and connection type documented in [Platform setup and capabilities](PLATFORMS.md).

Pass `SocialPage.nextCursor` back to the same account and operation until it is absent. Treat cursors as opaque. Capabilities reflect the adapter and known grants. The provider can still reject an action based on roles, account state, or product access.

The added providers have no SDK-level create idempotency guarantee. A draft UUID correlates a `publishOutcomeUnknown` error with the original user action. For a multi-step publish, a failed processing check can leave an unpublished container. A timeout or malformed response on the final publish can leave a published post. Check the provider feed before sending another create.

## Optional SwiftUI components

Link `SocialKitUI` alongside `SocialKit`. The connection view takes your existing `SocialClient.connect` closure, so the host owns account selection, app registration and the authentication browser. The publishing form accepts a text binding, the selected attachments, and `try await client.capabilities(for: account.id)`. Set the form’s view identity to the selected account ID when switching accounts so an earlier result stays with its account.

```swift
import SocialKit
import SocialKitUI
import SwiftUI

// In a view with a selected account and its capabilities:
SocialPublishForm(text: $text, media: attachments, capabilities: capabilities) { draft, media in
    if media.isEmpty {
        return try await client.publish(draft, as: account.id)
    }
    return try await client.publishMedia(media, draft: draft, as: account.id)
}
.id(account.id)
```

`SocialConnectionButton` reports progress and a connected account. Both controls cancel their pending task when dismissed. The publishing form stops further submissions after an uncertain write until the person acknowledges they checked the provider. The host can save the draft in its publishing closure for reconciliation after relaunch.
